# 架构与公开预览边界

```mermaid
flowchart LR
  A[行情 / 新闻 / 事件] --> B[时效与完整性准入]
  B --> C[角色契约 / 规则策略 / 量化排序]
  C --> D[确定性许可与风控]
  D --> E[模拟撮合与费用]
  E --> F[追加账本 / 对账 / 归因]
  F --> G[V7 只读工作台]
```

原系统将数据完整性、投资观点与交易许可分开。六个收益账户采用统一的虚拟初始资金和撮合纪律；风险观察角色不交易。正式赛季必须有身份、账本和治理证据；缺失状态保持 HOLD，公开预览没有绕过该限制。

公开入口 `scripts.public_preview` 是独立的只读进程：挂载原 V7 聚合 API 和界面，不启动原调度器、托盘或看门狗。API 缺数据时返回不可用或降级，而不是生成假的账户状态。它拒绝写请求，并在加载配置前设置公开预览模式，屏蔽私有 `.env`/连接档与进程中的 LLM/Webhook 凭证。

`scripts.public_demo` 只覆盖规则、费用、撮合与账户核对。三条历史未复权价格作为输入，买入来自预设情景；不是角色策略发出的真实信号，也不包含 LLM 推理或模型排序。撮合器的可注入时钟只用于该隔离回放，默认仍使用实际时钟；正式激活、市场时段和新开仓数据准入没有改变。

回放临时账户位于操作系统临时目录，使用 `PUBLIC-HISTORICAL-DEMO` 标识，不使用正式赛季命名空间。演示 JSONL 记录仅作假设回放核对，不冒充正式赛季事务账本。

原代码和公开整理副本的边界、缺陷与验证范围见 [已知问题](KNOWN_ISSUES.md) 和 [公开范围说明](PUBLIC_RELEASE_NOTES.md)。
