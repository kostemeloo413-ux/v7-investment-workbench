# 维护计划

本页列出待完成工作与验收条件，不表示相关能力已上线。实施顺序根据依赖完整性、可验证性与维护成本确定。

| 顺序 | 工作项 | 验收条件 |
|---|---|---|
| 1 | 规则与版本一致性 | 角色摘要、合同、扫描器和执行规则有明确版本映射；冲突有记录；韩叔/Cool 在规则和证据确认前保持停用 |
| 2 | 缓存与上下文版本 | 新闻缓存绑定模型、提示词、合同和上下文摘要；版本改变后不复用不兼容结果 |
| 3 | 隔离语义评测 | 冻结样本、简单基线、评分规则、失败样例和费用报告齐全；评测不写入生产研究数据 |
| 4 | 决策证据组织 | 结论可定位到来源、时间、对象、触发条件及缺失条件；事实、推断与预测可区分 |
| 5 | 反馈与教训归属 | 关联当前赛季、决策和成交身份；旧账本经验明确标识，不自动解释为现行策略效果 |
| 6 | 数据与运行维护 | 持续核对自然日终恢复、有限重试、当前报价、退出检查、账户对账及状态新鲜度 |

## 实施约束

优先复用已有 SQLite、聚合 API、调度和账本。按任务检索少量相关证据，并记录来源、时间和版本；结构化输出仍需本地业务校验。

新模型、检索或编排方案应与简单基线比较质量、延迟、调用数和费用。新增依赖须有可复现输入、失败处理和回滚方式。

公开内容继续保留来源、合成数据标记及许可范围说明。代码、模型资源与第三方材料的授权范围需分别明确，发布检查遵循现有文件白名单和完整历史扫描。
