# 验证说明

## 验证层次

| 层次 | 验证内容 | 结论边界 |
|---|---|---|
| 工程与规则 | 入口、隔离、行情适配、撮合、T+1、费用、账本和恢复 | 通过测试说明指定输入下的行为符合断言 |
| 语义质量 | 结构、引用、实体、事件、推论支撑和应拒答场景 | 需固定样本与评分规则；文本不同不等于正确 |
| 研究效果 | 排序、校准、成本、回撤及基线比较 | 依赖数据、时间切分、标签和执行代理 |
| 自然运行 | 按实际时间进行的数据更新、周期执行、对账和观察 | 不能由离线回放替代 |

公开回放验证工程流程，不生成模型效果或盈利结论。模拟成交数量与界面合成指标也不能替代效果评估。

## 支持的离线检查

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -B -m pytest -q
.\.venv\Scripts\python.exe -B -m scripts.public_preview --check
.\.venv\Scripts\python.exe -B tools/check_public_release.py --git
```

默认测试集合在 `pyproject.toml` 中定义，覆盖公开入口、无私有状态启动、只读边界、历史撮合、数据适配与交易恢复回归。合成行情、临时账户和 SQLite 用于隔离执行。

仓库同时保留历史测试，部分依赖未分发的旧审查材料、赛季或数据库。默认测试通过不表示全部历史测试、所有平台、完整实时环境或研究效果均通过。

## CI 与发布检查

`.github/workflows/ci.yml` 在 push、pull request 或手动触发时运行：完整 Git 对象与敏感信息检查、独立 Gitleaks 历史扫描、公开测试集合及历史回放。工作流固定上游 Action 提交，使用只读仓库权限。

每次发布还需检查目录及完整历史，复核新增文件与截图。实际结果应关联精确提交和工作流运行，不能把本地检查当成远端 CI 结果。[隐私检查](PRIVACY.md)

## LLM 评测现状

`scripts/analysis/eval_set.py` 包含固定陷阱类别及数据库样本，主要检查观点文本差异、立场分布、引用和模板化问题；`tests/relevance_eval_set.json` 与 `tests/run_eval_quick.py` 提供新闻规则层回归。

这些检查尚不能充分证明实体映射准确、引用支持结论或多视角优于单视角。`confidence` 尚不能解释为经过校准的正确概率。

LLM 评测会调用分析入口；该入口会写缓存并尝试保存事件因子。新增合成评测必须使用隔离缓存、临时数据库和独立输出，避免写入正式研究材料或赛季状态。

## 后续评测协议

以下为待实施工作，尚无对应效果成绩：

1. 固定开发集与冻结测试集；同一事件和近重复文本放入同一集合，记录来源及可见时间。
2. 在相同任务上比较规则、单视角、多视角和证据增强方案，记录各自上下文、调用数和费用。
3. 分别统计结构合格率、引用命中、实体/事件抽取、人工结论支撑、应拒答拦截及不必要拒答。
4. 按样本数与原始计数报告结果，单列失败、超时、重试和缓存命中；关键语义样本进行人工复核。
5. 记录模型、提示词、规则、输入摘要和上下文版本，使结果可追溯；重复评估敏感场景以观察稳定性。

如评估使用效率，另行对照任务完成时间、正确性及依据定位能力。用户偏好反馈与结论正确性分别记录。

## 研究与实际时间观察

研究报告需冻结时间切分、日期有效股票池、标签、特征、模型、费用、滑点和基线。披露缺失数据、样本量与日线代理偏差，避免将历史可见范围之外的信息用于当时判断。

实际时间观察需冻结模型与规则，记录每个交易日输入资格、执行周期与对账证据。只有满足正式资格要求的日期才能累计合格 Forward 天数。观察记录与历史回放使用不同命名空间和报告口径。
